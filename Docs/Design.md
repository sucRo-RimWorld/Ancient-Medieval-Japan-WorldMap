# Ancient & Medieval Japan - WorldMap — Design

**Repository:** `sucRo-RimWorld/Ancient-Medieval-Japan-WorldMap`. This is the **single canonical owner** of the optional fixed Japan archipelago Worldbuilder map preset and its future production release. The original Project [JapanWorldMapCandidate research](https://github.com/sucRo-RimWorld/Ancient-Medieval-Japan-Project/blob/main/Docs/Research/JapanWorldMapCandidate.md) is prior research/evidence and superseded prototypes, **not another active implementation owner**.

**Author's latest decision 2026-10-17: WorldMap development must REMAIN ACTIVE until all four observed issues are corrected: ocean faction bases; too few subalpine and alpine regions; practical ordinary highland settlement sites; Fuji/Tateyama/Hakusan and similar approved sacred summits individually protected as impassable Alpine.** The earlier 'pause now while Environment forests mature' direction is superseded. Keep the accepted Japanese shape. Implement limited highland source improvement **without waiting for all wetland/forest-food content to finish**, coordinate new biome names with Environment, and perform one final native 1.6 playable review before pausing. 1.7, optional scenery, new features and public Workshop upload do not become automatic release targets.

## Purpose and user-visible target

An **optional**, fixed ancient-to-medieval Japanese world for RimWorld 1.6/target 1.7, built as a Worldbuilder saved preset. It is not a replacement for Environment's procedural/random planet. Target the Japanese islands supported by the original polygon selection (Honshu, Shikoku, Kyushu and ten other selected island polygons), **without Hokkaido or Ryukyu/Okinawa**, and preserve geography-specific climate and biomes rather than using the virtual globe's fantasy latitude as evidence of real Japanese vegetation.

The current 1.6 prototype has 590,492 planet tiles, 50,810 land-labelled tiles and 13 island components. A **recognized shape** is already demonstrable, but this is **not** an accepted final grid size, historical coastline, reliable ecological distribution or recommended normal public release. The generated preset is not committed source; its licensed-GIS/terrain inputs are re-created by the builder.

## Source of truth and constraints

- `Tools/Production/JapanWorldPresetBuilder16.cs`: in-game original terrain/preset export.
- `Tools/Production/AMJJapanWorldPresetRestore16.cs`: shipped runtime component, limited to this preset, preserving Worldbuilder's terrain mutator reset and avoiding random-world changes.
- `Tools/Production/build_japan_world_preset16.py`: temporary isolated production build, explicitly requested, using the Project shared native 1.6 host helpers (not duplicated here). The `--acceptance` option uses `accept_japan_world_preset16.py` and `JapanWorldPlayableAcceptance16.cs`; **never** a PR/push-triggered native test.
- `Tools/Research/BuildJapanCoastlinePrototype.py` and `ProjectJapanCoastlineToTiles.py`: transform GSHHG/basemap-data coastline into original native tile mask. Retain original GSHHG LGPL-3.0-or-later source attribution and derivative disclosures before public release; do **not** commit original provider polygon data without license review.
- `Tools/Research/BuildJapanRegionalTerrain.py`: bounded official GSI DEMGM z8 pixel reading, JMA 1991–2020 12-station monthly temperature and 12-station annual rainfall interpolation; create provisional Kira WI+CI biome classes. Never claim medieval observations or exact forest composition.

Current approximate forest/mountain 1.6 land-tile counts are Warm 32,893 (64.7%), Cool 16,616 (32.7%), Subalpine 1,268 (2.5%), Alpine 33 (0.1%). **These are research output, not historical vegetation proportions.** Temperature band classes only; an intermediate-temperate forest band is currently **absent**. Elevation provenance: 50,438 actual samples, 338 labelled local DEM estimates, 34 missing elevation sources given only separate 1m *gameplay* fallbacks. The exact terrain, rain, rivers and forest outputs should not be used as historical claims. The current Worldbuilder virtual-planet latitude causes **incorrect local seasons**, a separate unresolved fix.

The island mask uses independently sourced modern GSHHG and explicitly excludes Hokkaido, Okinawa, Yakushima and Tanegashima for the current prototype; this is a **design exclusion** not proof those islands were historically absent. Current DEM z8 misses some high/narrow summits; rainfall has twelve-station IDW smoothing and the in-game river network is a relief-guided procedural heuristic, **not surveyed original medieval river lines**.

## 2026-10-17 author's original 1.6 in-game review and follow-up

**Actually inspected by author:** 13-island Japanese **overall coastline/silhouette accepted (shape OK)**. Preserve existing approved island mask and original geographical layout. The user reported that **some generated nonplayer faction settlements are displayed on sea**; this is a demonstrated gameplay defect, not a potential future nice-to-have. They reported **too few subalpine/alpine cells** and that alpine-looking sites were overwhelmingly uninhabitable. New objective: **more settleable high-country and some genuinely inhabitable subalpine/alpine colony-map sites**, but **Fuji and other established sacred summit tiles must be impassable Alpine**, while surrounding slopes/foothills remain available for settlement.

### Offshore faction location (targeted source change; native acceptance open)

Worldbuilder 1.6 calls its terrain restoration **after** Vanilla generation, in `World_FinalizeInit_Patch.RestoreWorld`; original Worldbuilder's `saveBases=false` route does not replace randomly placed faction bases. When the map becomes Japan-only, those old bases may remain at newly ocean-designated locations. WorldMap's shipped compatibility DLL now extends its existing `RestoreTerrain` Harmony patch with a **postfix** that: identifies nonplayer `Settlement` objects on ocean/impassable cells; selects unused, original-engine-approved settlement positions on the restored actual Japanese land; moves the **existing** settlement instances (maintain faction/name/load-ID) through world object remove/add indexing; and verifies no invalid nonplayer settlement remains. It runs only for the exact `AMJ_Japan_World_Prototype` preset during fresh-world restore, never for arbitrary Worldbuilder presets, ordinary procedural Environment worlds or load-time reinitialization. **No existing user save is retroactively altered.** Do not claim successful final placement until one revised-preset native run observes the correct in-game world.

### Mountain hilliness vs. alpine biome are different axes

- Original source incorrectly made **every tile over 2,400 m `Hilliness.Impassable`**, irrespective of sacred status; `AMJ_AlpineZone` is instead an actual loaded Environment **BiomeDef with nonzero `settlementSelectionWeight`**. One need not forbid settlements across an entire climate vegetation zone.
- **Source change:** non-sacred high-altitude tiles `>1500 m` have `Hilliness.Mountainous` rather than indiscriminate `Impassable`. Normal engine `TileFinder.IsValidTileForNewSettlement` and WorldMap terrain conditions still govern final settlement. This makes existing **non-sacred alpine** tiles candidates where the base game's rules permit, not proof of all-alpine colony viability.
- **Sacred summit exceptions:** the three traditionally designated sacred mountain peaks—**富士山 / Mt Fuji, 立山（雄山） / Mt Tateyama (Oyama), 白山（御前峰） / Mt Hakusan (Gozengamine)**—each map to **one closest real GIS-positioned Japanese land cell** (with a bounded 0.18-degree geographic proximity gate); the selected summit cell gets `AMJ_AlpineZone` and `Hilliness.Impassable`. Surrounding hills/valleys do not inherit this ban. This is a **specific symbolic summit placement overlay**, not a false claim that the sampled z8 DEM/modern climate measured the peak at 3,776 m or a historical snowline. **Do not assign other sacred mountain identities or sacrifice historically populated temple slopes by a broad mountain-wide lock.**
- **Active correction:** increase mountain evidence resolution, **not arbitrarily inflate alpine percentages**. Old 1.6 prototype used coarse GSI Global Map **DEMGM z8**; 1,268/50,810 subalpine (2.5%) and 33/50,810 Alpine (0.1%) were the *old output*, not accepted final targets. **New producer source now uses GSI Fundamental Geospatial Data DEM10B `dem_png` at z9**, with each relevant original Japan native-grid land centre sampled at geographic coordinates; still no arbitrary extrapolated mountain altitude. z9 is roughly twice the pixel resolution per axis of z8 and uses better observed input. Verified source availability and encoding: [GSI elevation data](https://maps.gsi.go.jp/development/index.html) and [elevation PNG specification](https://maps.gsi.go.jp/development/demtile.html). Preserve the existing JMA twelve-station monthly WI/CI thresholds (warm≥85 & CI≥−10, cool≥45, subalpine≥15, alpine<15); keep a bounded download cap, exact source hashes, unresolved DEM and interpolated-value labels. The source-only change **does not yet prove area growth**; recalculate native world class counts and practical mountain settlement in the next one-shot acceptance. If highland distribution is still visibly deficient, continue this work rather than declare pause or a proportion target, using evidenced mountain DEM/treeline source improvement with Environment biome identities.
- **Next one-shot native test asserts:** all surviving nonplayer settlements are nonocean/passable; both subalpine and alpine counts strictly exceed the former DEMGM z8 1,268/33 baselines **without forcing biome proportions**; at least one open settlement site exists for each mountain Biome; exactly three Alpine/Impassable summit cells are present; the prior world silhouette/land tile count and full save/reload remain intact. This is a minimum engineering improvement gate, **not** proof that high-country visually matches the final historical landscape. 

**Completion criteria:** revise the eligible mountain cell count and nonplayer settlement placement with **one consolidated** real 1.6 native preset/new-world acceptance after the revised source + ecological regional design are coherent. Check that all nonplayer settlements are on actual nonimpassable Japan land, at least one reasonable ordinary subalpine and alpine colony candidate exists, Fuji/Tateyama/Hakusan peak cells are Alpine/Impassable, no accidental geographic silhouette change, and fresh save/reload remains functional. Avoid repetitive player PC/test-runner load; this work is **source-only until that final check**.

## Ownership boundary, backlog and stop

1. **Environment** owns biome identities, regional tree species, intermediate-temperate ecosystem decision and a future twelve wild-food inclusion. WorldMap merely assigns **known, loaded** Environment BiomeDefs on its fixed preset. Never independently add a competing Forest BiomeDef to WorldMap.
2. **WorldMap** owns its preset resolution, coastline/river/elevation representation, geo-position mapping, static biome placement, Worldbuilder compatibility and optional packaged map.
3. Grains/Rice/Wild Food supply balance is evaluated in full AMJ separately; the presence of natural foods does not require WorldMap to implement food production or PlantDefs.
4. **Do not pause WorldMap yet.** Complete observed ocean-faction, subalpine/alpine sparsity, highland settlement and sacred summit problems first. The first DEM10B z9 data upgrade is source implemented; final geographic band distribution remains an **open acceptance item**, not solved by naming a higher zoom. One manual 1.6 producer/native acceptance after source changes can establish actual band counts and placement; if results fail user intent, improve documented DEM or evidence-based forest-limit mapping and focused retest. **Only after the four issues pass should optional expansion go on HOLD** pending broader Environment forests. Forest-food Jobs, all wetland art, 1.7 and public release are not blockers for the four existing WorldMap defects.
5. **No Steam/public release** until original GIS/DEM terms and attribution, Mod package identity, true Worldbuilder selection, available platform profiles, geographic/ecological limits, privacy/publication gates and acceptance are satisfied.
